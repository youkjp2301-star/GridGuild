# 목적지 변경 테스트와 피드백 — 0.5.0

확인일: 2026-11-05 (Asia/Seoul). 표준 Android API 34, 800×1280 에뮬레이터에서 실제 앱을 실행했다.
Mock UI 실행, 공식 SDK 타입을 사용하는 테스트 전송 계층, 실제 Pleos 서비스 검증을 구분한다.

## 사용 흐름과 버튼의 역할

정상 흐름은 **내비 목적지 변경 → GridGuild 자동 재조회 → 목적지 주변 충전소 갱신**이다.
새로고침은 목적지 변경 알림이 늦거나 연결을 다시 확인할 때 쓰는 수동 재조회이며 목적지 선택 버튼이 아니다.
재탐색은 내비의 활성 경로를 다시 탐색하도록 요청하는 별도 기능이다. 두 버튼은 보조적인 ‘내비 연결 도구’에 접었다.
Mock에서는 ‘목적지 변경 (테스트)’가 내비의 목적지 변경 상황을 재현한다. 실제 내비 앱이나 차량의 목적지는 바꾸지 않는다.

## 실제 실행에서 확인한 결과

| 시나리오 | 결과 |
|---|---|
| 기본 삼락 목적지 | 반경 5 km에 삼락 강변 1곳 표시 |
| 센텀시티로 변경 | 센텀·광안 2곳 자동 표시, 센텀이 첫 후보 |
| 광안리로 변경 | 동일 권역의 2곳 유지, 광안이 첫 후보로 변경 |
| 기장 해안으로 변경 | 샘플 후보 0곳 안내. 실제 충전소가 없다고 주장하지 않음 |
| 랜덤 목적지 | 준비된 네 위치 중 현재와 다른 위치 선택, 후보 자동 갱신 |
| 목적지 변경 전후 | 충전소 자체의 좌표는 고정. 개인·도시 XP는 변경하지 않음 |
| 미션 시작 후 목적지를 기장으로 변경 | 기존 삼락 미션 유지. 충전 ON·SOC +2% 후 개인/도시 각 120 XP 지급 |
| SOC 90% / 89% 전환 | ‘충전 추천 중지’와 후보·위치도 복귀를 구분. 지역에 시설이 없다는 뜻으로 표시하지 않음 |
| SDK 목적지 변경 이벤트 | FakeNaviClient에서 onDestinationChanged → 재조회 → 신규 좌표 → 후보 갱신 확인. 실제 SDK 성공으로 집계하지 않음 |

자동 테스트 **45개 단위 + 24개 에뮬레이터 테스트** 통과. 에뮬레이터 테스트는 화면 16개, 저장 코덱 3개, 내비 테스트 전송 계층 5개다.
자동화 외에 일반 실행 상태에서도 센텀→광안리→기장을 직접 눌러 위 후보 수/첫 후보를 확인했다.
작업 전 사용자 데이터를 백업/복원했고, 이 수동 테스트 후에도 저장 파일과 백업의 SHA256이 같았다.
PNG 및 UI XML 근거는 Git 제외 경로 `artifacts/destination-demo/`에 보관했다.

## 검토 중 반영한 개선

- Aside 코드 검토를 받아 고SOC를 ‘주변 0곳’으로 오해할 수 있던 제목을 수정하고 위치도를 숨겼다.
- 목적지와 가까운 충전소 핀이 겹치던 부분은 실제 좌표 점과 번호 표식을 연결해 구분했다.
- 진행 미션에 원래 충전소 이름과 목적지 변경 후에도 유지된다는 설명을 추가했다.
- SDK 모드의 빈 후보 안내에서 사용할 수 없는 ‘테스트 목적지 선택’ 지시를 제거했다.
- 가상 시설·직선거리·위치 관계도라는 범위를 표시하고 접근성 설명에 충전소 이름/거리를 포함했다.

## 아쉬운 점과 다음 우선순위

1. **실제 연동의 가장 큰 제약:** 이전 Pleos 실응답 검사에서 목적지 콜백이 오지 않았다. 이번 테스트로 실제 내비 앱→GridGuild 연동 완료를 주장할 수 없다. 활성 내비 안내 상태에서 목적지 변경·경유지·재탐색 종료를 검증하는 것이 우선이다.
2. **데이터 다양성:** 가상 충전소가 3곳뿐이라 센텀과 광안은 후보가 겹치고 순서만 바뀐다. 이는 반경이 겹친 결과지만, 체험의 다양성은 제한된다. 실제 충전소 API와 운영/가용 상태가 있어야 실사용 추천이 가능하다.
3. **거리 기준:** 현재는 목적지 기준 직선거리다. 실제 도로 우회 거리·이동 경로·도착 예상 SOC를 고려하지 않는다. 실제 경로 형상 계약/데이터가 확보된 뒤 추천 근거를 확장해야 한다.
4. **화면 밀도:** 800×1280 세로 화면에서도 위치도 아래의 미션 시작 버튼은 스크롤해야 한다. 위치도 접기 또는 넓은 화면의 좌우 배치가 다음 UX 개선에 적합하다. 가로 차량 화면과 큰 글자 설정은 이번에 추가 검증하지 않았다.
5. **지도 표현:** 위치 관계도로 후보 변경은 보이지만 도로·해안·랜드마크가 없어 실제 지도보다 공간감이 약하다. 목적지 부근 번호/중앙 표기도 확대나 범례 개선 여지가 있다. 실제 지도로 보이게 꾸며 지원되지 않는 지도 기능을 주장하지 않는다.
6. **테스트 재개:** Mock 목적지는 연결 세션에만 유지되며 앱 프로세스를 재시작하면 삼락으로 돌아간다. 반복 QA를 위해서는 마지막 테스트 목적지 저장을 선택 기능으로 추가할 수 있다. 야간 미션은 실제 한국 시간대 제한을 지키므로 주간에 시작할 수 없다.

현재까지 확보한 근거는 **실행 가능한 Mock 체험과 콜백 처리 코드의 검증**이다. 실제 시설·경로·내비 종단 검증은 별도로 남아 있다.
