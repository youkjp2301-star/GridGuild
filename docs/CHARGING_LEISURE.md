# 충전 중 즐길거리 · 0.12.0

기준:2026-11-11 사용자 추가 요구, PRD18절. 이번 장소 데이터는 전부 가상이다.

## 사용 흐름

ROUTE CHARGE의 기존 충전소 카드 → **충전하는 동안 뭐 하지?** → 카테고리 필터 → 상세보기.
시트의 뒤로 화살표로 목록에 돌아오고 X/닫기로 원래 ROUTE에 복귀한다. 장소 선택은 미션 시작·경유지 추가·목적지 변경·XP 지급을 실행하지 않는다.
실제 P단/플랫폼 UX 허용 조건을 유지하며 제한 시 열린 시트도 숨기고 닫는다.

## 장소 데이터와 거리

- core의 `LeisurePlaceRepository.nearby`가 `LeisurePlaceSnapshot`을 반환한다. 현재 `MockLeisurePlaceRepository`만 연결한다.
- 6개 고정 가상 충전소마다5곳, 총30개의 가상 카페/산책·공원/음식점/팝업·행사를 둔다. 이름에 가상을 표시하고 실제 업체·영업/행사 정보를 연결하지 않는다.
- `LeisurePlace`는 충전소 식별자, 좌표, 카테고리, 추천 활동·시간, 설명, 광고, 혜택, 출처/관측 시각/외부 식별자를 분리한다.
- Haversine 직선거리≤300m만 추천한다. 부동소수 오차 허용은0.000001m다. 목적지 반경5km의 충전소 후보 계산과 별개다.
- 실제 보행 데이터가 없으므로 `walkingMinutes=null`이고 UI는 **도보 시간 미확인**이다. 도보거리·횡단·영업·예약·복귀 가능성을 추측하지 않는다.
- 카카오맵/Google Places 등을 도입할 때는 Repository 어댑터, 출처/이용허락 표시, 좌표·광고·영업 갱신 정책을 추가한다. 실제 API·인증키는 현재 없다.

## 충전 시간과 추천 규칙

필요 에너지(kWh)=용량(kWh)×(목표SOC−현재SOC)/100.
예상 충전시간(분)=필요 에너지÷**평균 실효 출력**(kW)×60.

충전기 정격 최대 출력과 평균 실효 출력을 같은 값으로 취급하지 않는다. 충전 제어나 실제 완료 보장이 아닌 간이 추정이다.
현재42%→목표62%,60kWh,36kW의 **명시적 Mock 계산**은20분이다.

- SOC0~100, 목표>현재, 양의 유한 용량/출력을 요구한다. 결측/NaN/무한대/목표 도달/출처 불일치/오래된 동적 관측/미래 시각이면 추정하지 않는다.
- 실제 동적 관측은 출처를 확인하고10초 신선도를 적용한다. SDK 용량/출력이 미연동인 현재 실제 모드에서는 일반 장소만 보여준다.
- Mock의 정적 계산 가정은 별도 플래그로 구분하고 관측 시각을 매번 새로 발행하지 않는다. 모든 입력이Mock일 때만 정적 가정을 허용하며 SOC 신선도는 계속 확인한다.
- 시트 목표의 초기값은 저장된 HOME 목표 또는 빈값이다. 없는 목표를 임의로 채우지 않는다. 시트의 명시적 입력은 HOME 저장값을 덮어쓰지 않는다.
- 예상시간의 내림값에서 복귀 여유5분을 뺀 활동 예산으로 분류한다.20분이면15분 이하 활동이 우선이고, 이후 직선거리/안정적ID로 정렬한다. 화면 반올림 때문에 활동 예산을 늘리지 않는다.
- 실제 보행 시간을 모르는 상태의 **활동시간 적합성 참고**다.20분 안에 다녀올 수 있음을 보장하지 않으며 시간 데이터가 없어도 일반 장소 목록/필터는 유지한다.

## 광고·혜택·보상

`isAdvertisement`는 카드/상세의 광고 배지만 결정한다. 반경·카테고리·시간 적합성·거리 정렬에는 가산하지 않는다.
`LeisureBenefit`은 향후 제휴 연결용 표시 메타데이터이며 현재는 **예시 혜택 · 발급 불가**다.
결제/쿠폰 발급/바우처 사용/포인트 환전/소비 포인트 잔고는 구현하지 않았다. 기존 `PointEvent`는 충전 미션의 데모 XP 원장으로 유지한다.
장소 탐색·광고 열람을 소비 리워드 또는 충전 성과로 기록하지 않는다.

## 장소 목적지 설정 (0.13.0)

카드의 상세보기 옆과 장소 상세 하단에 **목적지 설정**을 제공한다. `NavigationTarget`은 충전소·미션 ID와 분리된 이름/좌표이며, 선택 장소가 해당 충전소의 직선300m 안에 있는 유효한 Mock 데이터인지 확인한다.
가상 장소는 Mock 내비 목적지에만 반영하고 현재 진행 미션과 XP 원장은 변경하지 않는다. 실제 SDK 모드에서는 이 버튼을 비활성화한다. 장소 API가 연결될 때는 원천 검증과 실제 내비 종단 확인이 추가로 필요하다.
NaviHelper 저장소에는 일반 좌표를 공식 `RouteInfo`로 보내고 일치하는 좌표 응답만 성공으로 확인하는 경로를 추가했다. 이 경로의 fake-client 검증은 실제 Navi Service 성공과 구분한다.
목적지 접미어와 반복되는 데모 설명은 일반 화면에서 정리하고 상단 체험 모드 안내에 모았다. 가상 장소/광고/예시 혜택 표시와 실제 결측 안내는 유지한다.

## 도시 레벨 ±1

`DemoCityLevels.step`은 선택 지역의 다음/이전 레벨 기준 XP와 현재 XP의 차이를 `TEST_LEVEL` 조정 이벤트로 저장한다.
원래 이벤트를 삭제하지 않고 개인 credit/미션 완료 credit을 주지 않는다. 낮추기는 음수 도시 조정이며 데이터 코덱으로 그대로 보존한다.
개인 XP·다른 지역·진행 미션·충전 완료 기록은 유지한다. 해당 테스트 이벤트는 새 XP 획득 애니메이션으로 재생하지 않는다.
Lv.1/12 경계는 비활성이고, 실제 SDK 모드/다른 지역 요청/플랫폼·주차 제한은 원자 저장 시 다시 확인한다.
