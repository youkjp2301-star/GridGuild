# ROUTE CHARGE 충전기 이용 현황 · 0.9.0

2026-11-09 UI 수정: 카드의 확인 시각·정상 호환 문구·반복 Mock 문구·일반 미확인 경고를 제거했다. 데이터의 관측 시각/신선도 검사는 유지한다. 상태와 대수는14~16sp로 표시하고 미확인 재고는 ‘정보 없음 · 총5기’처럼 간결하게 표시한다. 상세 추천 안내/커넥터/상태 섞기는 상단 조절 아이콘, 개별 상태 테스트는 카드의⋮에 있다.

Mock은 기본 첫 안내 지점만 여유를 유지하고 다른5곳에 여유/혼잡2/자리 없음/정보 없음 조합을 무작위 배정한다. 수동 섞기는 전체6곳을 섞는다. 전경에서60초마다 fixture 관측을 다시 발행하므로 기존10분 경과 후 전부 정보 없음이 되던 현상을 막는다. 수동 UNKNOWN/STALE/MISSING 시나리오는 주기 갱신에서도 유지하며 실제 제공자 데이터의10분 정책은 완화하지 않는다. 시각에 따라 목록을 매번 무작위로 흔들지는 않는다.

아래0.8.0의 데이터 계약은 유지하며 화면의 시각 표시/옛 테스트 메뉴 위치 설명은 위 변경 사항을 따른다.

2026-11-09 사용자 요청. 기존 추천 카드 안에 상태·수량·커넥터·확인 시각을 통합한다. 실제 충전소 API는 연결하지 않았으며 Pleos 차량 모드에서도 충전기 현황은 **MOCK**다.

## 배지와 집계

| 배지 | 규칙 | 표현 |
|---|---|---|
| 여유 | 신선하고 완전한 데이터, AVAILABLE/전체 ≥50% | 녹색 |
| 혼잡 | 신선하고 완전한 데이터, AVAILABLE ≥1, 비율 <50% | 주황색 |
| 이용 가능 없음 | 신선하고 완전한 데이터, AVAILABLE=0 | 회색 |
| 정보 없음 | 미수신·누락·중복 ID·잘못된 전체 수·미확인 상태·시간 이상·갱신 지연 | 연한 회색 |

고장·점검·운영 중단·사용 중·미확인은 AVAILABLE 수에 포함하지 않는다. 0기와 미확인은 구분한다. 전체 수가 유효하고 일부 관측만 신선하면 확인된 가용 수와 ‘일부 미확인’을 표시하되 상태 배지는 정보 없음이다. 이는 실제 현재 가용 수의 하한이나 도착 시 가용성을 보장하지 않는다.

갱신 지연 기준은 제품 정책상 **10분 초과**다. 미래 시각은 미확인으로 취급한다. 저장된 상태의 마지막 **관측** 시각과 수집 시각 중 가장 오래된 시각을 표시/검사한다. 상태가 오래 바뀌지 않았다는 이유만으로 오래된 정보로 판정하지 않는다.

충전소 전체 가용 대수와 차량에 맞는 커넥터의 가용 대수를 구분한다. 혼합 충전소에서 두 값이 다르면 차량에 맞는 수량을 추가 표시한다. 커넥터 정보가 불확실하면 0기라고 단정하지 않는다. Mock 차량은 기본 DC콤보이며 변경 가능하다. 실제 차량의 커넥터 능력은 현재 SDK 경로에서 수집하지 않아 미확인으로 표시한다.

## 추천·선택

- 목적지 반경5km는 기존 직선거리 필터를 유지한다. 실제 경로 형상/우회거리 조회는 미연동이며 카드에 ‘경로 이탈 미확인 · 목적지 직선 n km’를 표시한다. 직선거리는 경로 이탈 거리나 도착시간이 아니다.
- 알려진 커넥터 불일치는 마지막으로 배치한다. 그 외에는 거리+상태 가중치(여유0/혼잡1.5/정보 없음2.5/자리 없음8)로 정렬하고 직선거리·충전소 ID로 동률을 안정적으로 정렬한다. 가까운 혼잡 후보가 매우 먼 여유 후보보다 앞설 수 있다.
- 거리 항목에는 향후 실제로 받은 이탈 거리가 있으면 사용하고 없으면 목적지 직선거리 대리 지표를 쓴다. 없는 경로 데이터를 만들지 않는다.
- 신선한 정보의 가용0기·호환 커넥터 빈자리0기·알려진 커넥터 불일치는 새 ROUTE 미션 참여를 제한한다. UI와 저장 직전 ViewModel에서 재확인한다. 이미 진행 중인 미션은 상태 변경으로 취소하지 않으며 SOC 판정·중복 방지·XP/도시 반영은 기존 엔진을 유지한다.
- 내비 경유지/목적지 요청 버튼과 NaviHelper 구조는 유지한다. 가용0기 카드에는 선택 전 확인 경고를 표시한다. 정보 없음은 이용 전 확인 안내와 함께 허용한다.
- ‘혼잡’은 사용 현황에 따른 간이 비율이며 대기 차량 수나 예상 대기시간이 아니다. 도착 전 상태가 변할 수 있음을 목록에 안내한다.

## Mock 직접 시험

1. 미션 → ROUTE CHARGE → 충전소 카드의 **상태 테스트**.
2. 여유(5/3)·혼잡(5/1)·이용 가능 없음(5/0)·정보 없음 중 선택한다. 별도로 오래된 정보·미수신도 확인할 수 있다.
3. 기본 삼락은 강변=여유/공원=혼잡. 센텀·광안 후보에는 자리 없음·여유·혼잡·오래된 정보가 섞여 있다. 목록 수·위치도 번호는 정렬 결과와 동일하다.
4. 목록 상단 내 커넥터(테스트)로 호환 여부/정렬을 바꿔 본다. 실제 차량 능력이나 내비 목적지는 바꾸지 않는다.
5. 상태 새로고침(MOCK)은 준비된 fixture를 다시 발행하고 결과 메시지를 표시한다. 한 충전소 상태를 바꿀 때 다른 충전소 관측 시각을 갱신하지 않는다.

시나리오와 Mock 커넥터는 세션 단위다. 앱 재시작 시 기본으로 돌아가며 XP 원장·HOME 설정·Navi 목적지와 별개다. 테스트 기능은 P단+플랫폼 UX 허용 및 Mock 모드에서만 조작할 수 있다.

## 데이터 경계와 향후 한국환경공단 어댑터

`ChargingAvailabilityRepository` → `StationAvailability`/`ChargerObservation` → core 집계·정렬 → 기존 Compose 카드로 분리했다. UI는 API 숫자 코드를 해석하지 않는다. 정규화 상태, 원본 코드, 커넥터, 관측 시각, 상태 변경 시각과 수집 시각을 별도로 가진다. 자격증명·실제 HTTP 클라이언트·승인된 API 키는 이번 구현에 포함하지 않는다.

Aside를 통한 [공공데이터포털 공식 명세](https://www.data.go.kr/data/15076352/openapi.do) 확인: `getChargerInfo`/`getChargerStatus`, `statId`/`chgerId`, `stat`, `statUpdDt`가 노출된다. `statUpdDt`는 상태 변경 일시이며 자체 관측 시각과 구분해야 한다. 상태 숫자별 코드 정의와 시간대는 이번 공개 자료에서 확정하지 못해 매핑을 구현하지 않았다.

향후 어댑터는 승인된 최신 계약의 코드·커넥터·시간대를 검증하고, 전체 목록과 증분 상태 조회를 구분해야 한다. 현재 가상 충전소 ID를 실제 사업자 ID와 암묵적으로 연결하지 않으며 실제 시설 카탈로그/식별자 연결을 먼저 검증한다. 페이지 누락/중복 제거·조회창 누락 복구·주기적 전체 동기화를 처리하며 증분 응답에 없다고 오프라인으로 바꾸거나 모든 충전기의 관측 시각을 새로 쓰지 않는다. 미매핑 코드는 UNKNOWN으로 보존한다. 실제 경로와 차량 커넥터 역시 검증된 별도 입력이 들어오기 전까지 미확인이다.
